# Detection of AI-Generated Hotel Reviews

English | [中文](README.zh-CN.md)

This project classifies English hotel reviews as written by a human (from Booking.com) or generated by GPT-4. The data is the English part of the MAiDE-up corpus (Ignat et al., NAACL 2025 Findings).

## Running

```bash
python src/split_data.py     # 1. make train.csv / test.csv
python src/train.py          # 2. tune and fit all five registered models, gb, lr, nb, rf, tree
python src/evaluate.py       # 3. evaluate the saved models on the final test set
python src/train.py nb lr    #    train only selected models
python src/train.py rf gb    #    train random forest and gradient boosting only
python src/compare_preprocessing.py   # optional: preprocessing comparison (Appendix C of the report)
```

### 1. Data split (`split_data.py`)

If `data/raw/all_data.csv` is missing, the script downloads it. It then:

1. keeps the 2000 English reviews (1000 human-written with `source = 0`, 1000 GPT-4 generated with `source = 1`);
2. joins the upside and downside parts of each review into one `text` field;
3. splits the reviews 75/25 into train and test, stratified on label × sentiment, with seed 42.

| split | human NEG | human POS | AI NEG | AI POS | total |
|-------|-----------|-----------|--------|--------|-------|
| train | 375       | 375       | 375    | 375    | 1500  |
| test  | 125       | 125       | 125    | 125    | 500   |

The counts are also written to `results/tables/split_summary.csv`.

### 2. Model training (`train.py`)

For each model, `train.py` runs a grid search with 5-fold stratified CV on the training set (the same folds for every model), refits the best setting on all 1500 training reviews and writes:

| output | content |
|--------|---------|
| `results/models/{name}.joblib` | final fitted pipeline |
| `results/tables/cv_{name}.csv` | CV accuracy (mean and sd) for every setting |
| `results/figures/cv_{name}.png` | tuning curve |
| `results/tables/feat_{name}.csv` | top 5 features |

The test set is not used here.

| model | pipeline | grid | selected | CV accuracy |
|-------|----------|------|----------|-------------|
| `nb` | bag of words → SelectKBest(chi2) → MultinomialNB | k ∈ {10, …, 1000, all}, alpha ∈ {0.1, 0.5, 1} | k = 750, alpha = 0.5 | 0.903 |
| `lr` | bag of words → LogisticRegression(penalty = "l1") | C ∈ 10^-2 … 10^2 (17 values) | C = 1 (203 of 1351 weights non-zero) | 0.915 |
| `tree` | bag of words → DecisionTreeClassifier | ccp_alpha ∈ {0, …, 0.05} | ccp_alpha = 0.002 (53 leaves) | 0.818 |
| `rf` | bag of words → RandomForestClassifier | n_estimators ∈ {100, 300, 500, 1000}, max_features ∈ {1, 3, log2, sqrt, 0.1, 0.3} | n_estimators = 1000, max_features = 3 | 0.919 |
| `gb` | bag of words → GradientBoostingClassifier | n_estimators ∈ {100, 200, 400, 800}, learning_rate ∈ {0.03, 0.1, 0.3}, max_depth ∈ {1, …, 5} | n_estimators = 800, learning_rate = 0.1, max_depth = 2 | 0.923 |

The first rf and gb grids selected values on their edge, so both grids were extended in that direction until CV accuracy stopped improving. max_features, learning_rate and max_depth are now selected inside the grid. The number of trees and stages is the largest value searched, but accuracy has levelled off: rf changes by at most 0.2 points between 300 and 1000 trees, and gb at learning rate 0.3 peaks at 200–400 stages.

In the tuning plots the error bars are the standard deviation over the 5 folds and the red star marks the selected setting. Curves that nearly coincide (the three alphas in nb, the three max_features values in rf) are shifted slightly along the x axis so their error bars do not overlap.

`lr.py` sets both `penalty="l1"` and `l1_ratio=1`. Before scikit-learn 1.8 only `penalty` is used, and `l1_ratio=1` alone silently gives an L2 model.

Top features:

- **nb**: log P(word | AI) − log P(word | human). Positive values point to AI, negative to human.
- **lr**: the coefficients. Positive values point to AI, negative to human.
- **tree**: Gini importance.
- **rf**: impurity-based feature importance aggregated across the forest.
- **gb**: impurity-based feature importance aggregated across the boosting trees.

### 3. Final evaluation (`evaluate.py`)

After training all five models, `evaluate.py` loads the saved pipelines and evaluates them on the same 500 test reviews. It treats AI-generated reviews (`label = 1`) as the positive class and writes the following files:

| output | content |
|--------|---------|
| `results/tables/test_metrics.csv` | accuracy, precision, recall and F1 for each model |
| `results/tables/confusion_{name}.csv` | confusion matrix for one model |
| `results/tables/test_predictions.csv` | review ID, label, sentiment and aligned predictions from all models |
| `results/tables/mcnemar_tests.csv` | exact McNemar tests for NB versus LR, tree versus RF and tree versus GB |
| `results/tables/rf_by_sentiment.csv` | random forest metrics for positive and negative reviews |
| `results/tables/rf_sentiment_fisher.csv` | Fisher exact test comparing random forest accuracy across the two sentiment groups |

The statistical tests use a significance level of 0.01. Running `split_data.py`, `train.py` and `evaluate.py` in that order reproduces the complete analysis from `data/raw/all_data.csv`. If the raw file is absent, `split_data.py` downloads it before creating the fixed train-test split.

### Using the modules

```python
from load_data import ReviewData
from preprocessing import TextPreprocessor

d = ReviewData.load("train")     # 1500 reviews; d.X = text, d.y = label, d.sent = sentiment
tr, va = d.split()               # 1200 / 300 hold-out split
folds = d.folds()                # 5 stratified folds, pass as GridSearchCV(cv=folds)
te = ReviewData.load("test")     # 500 reviews, final evaluation only

vec = TextPreprocessor().make_vec()   # unfitted CountVectorizer, put it inside a Pipeline
```

Splits and folds are stratified on label × sentiment (`d.grp`).

## Text preprocessing

1. lowercase, replace curly apostrophes by straight ones, remove accents;
2. keep alphabetic tokens only, including contractions such as wasn't; drop numbers and punctuation;
3. **keep stop words, no stemming, unigrams only**;
4. remove sparse terms with `min_df = 5` (terms in fewer than 5 reviews), which cuts the training vocabulary from 4737 to 1351 terms.

The vectorizer is the first step of every pipeline, so in CV each fold builds its vocabulary from its own training part only.

Other settings are available for comparison, e.g. `TextPreprocessor(stop=True, stem=True, ngram=(1, 2), min_df=10)`. `python src/compare_preprocessing.py` compares seven settings with 5-fold CV accuracy on the training set and writes `results/tables/preprocessing.csv`. It uses the same folds as `train.py`, naive Bayes with alpha = 1 and no feature selection, and L1 logistic regression whose C is chosen by an inner 5-fold CV (`LogisticRegressionCV`). Mean accuracy, with the sd over folds in parentheses:

| setting | features | naive Bayes | Lasso LR |
|---------|----------|-------------|----------|
| no sparse-term removal (min_df = 1) | 4737 | 0.894 (0.013) | 0.909 (0.022) |
| **chosen setting (min_df = 5)** | **1351** | **0.901 (0.010)** | **0.899 (0.022)** |
| min_df = 10 | 845 | 0.895 (0.010) | 0.907 (0.019) |
| stop words removed | 1138 | 0.897 (0.016) | 0.893 (0.013) |
| stemming | 1186 | 0.895 (0.013) | 0.905 (0.020) |
| stop words removed + stemming | 1003 | 0.885 (0.013) | 0.901 (0.020) |
| unigrams + bigrams | 3665 | 0.908 (0.011) | 0.906 (0.022) |

All settings lie between 0.885 and 0.909, and most differences are smaller than one CV standard deviation. No setting is clearly best, so the remaining choice rests on interpretability and vocabulary size:

- **Keep stop words**: removing them lowers both models slightly (NB 0.901 → 0.897, LR 0.899 → 0.893). Function words such as I, we and the carry writing style.
- **No stemming**: no consistent gain, and stems such as servic or lobbi make the top features harder to interpret.
- **min_df = 5**: cuts the vocabulary from 4737 to 1351 terms; NB gains 0.7 points and LR loses 1.0 point, both within the CV noise.
- **Unigrams only**: bigrams nearly triple the number of features for at most 0.7 points.

## Columns in the processed files

| column | description |
|--------|-------------|
| `id` | row number within the English subset |
| `text` | upside + downside review text (the only model input) |
| `label` | 1 = AI-generated (fake), 0 = human-written (genuine) |
| `sentiment` | `POS` / `NEG`, used to split the test set by sentiment |
| `upside`, `downside` | the two original review parts |
| `score`, `city`, `hotel` | metadata, not used as features |
